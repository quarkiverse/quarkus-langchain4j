= Redis Chat Memory Store

include::./includes/attributes.adoc[]
include::./includes/customization.adoc[]

By default, Quarkus LangChain4j keeps chat memory in the application's memory, so conversations are lost when the application stops or restarts.
The Redis chat memory store persists the chat memory of your AI services in Redis.
Conversations then survive restarts, and several instances of the application can share them.

See xref:messages-and-memory.adoc[Messages and Memory] for background on how chat memory works.

== Dependency

To use Redis as the chat memory store, add the following Maven dependency:

:provider-artifact: quarkus-langchain4j-memory-store-redis
include::./includes/quarkus-langchain4j-maven-dependencies.adoc[]

This extension builds on the https://quarkus.io/guides/redis[Quarkus Redis client].
Configure the Redis connection as described in that guide, for example:

[source,properties]
----
quarkus.redis.hosts=redis://localhost:6379
----

In dev and test mode, if no hosts are configured, the Redis Dev Services start a Redis container automatically.

Unlike the xref:rag-redis.adoc[Redis document store], the chat memory store only uses basic Redis commands, so it does not need the RedisJSON or RedisSearch modules.

== Usage

The extension registers a `ChatMemoryStore` bean backed by Redis.
Because it replaces the default in-memory store, AI services use it with no code changes:

[source,java]
----
@RegisterAiService
@ApplicationScoped
public interface Assistant {

    String chat(@MemoryId String conversationId, @UserMessage String message);
}
----

The memory window settings (such as `quarkus.langchain4j.chat-memory.memory-window.max-messages`) still apply: the store only holds the messages kept by the chat memory.

To delete a conversation from Redis, use `ChatMemoryRemover`:

[source,java]
----
ChatMemoryRemover.remove(assistant, conversationId);
----

== Data Format

Each conversation is stored as a Redis string:

* the key is the memory ID, converted to a string, with no prefix
* the value is the list of messages, serialized as a JSON array

For example, after a short conversation with memory ID `01`:

[source,shell]
----
> GET 01
"[{\"contents\":[{\"text\":\"Hello, my name is Ricardo\",\"type\":\"TEXT\"}],\"attributes\":{},\"type\":\"USER\"},{\"toolExecutionRequests\":[],\"text\":\"Nice to meet you Ricardo\",\"attributes\":{},\"type\":\"AI\"}]"
----

[IMPORTANT]
====
The memory ID is used as the key as-is, and keys never expire.
If the same Redis database holds other data, choose memory IDs that cannot collide with other keys, or use a dedicated Redis client (see below).
====

== Using a Named Redis Client

By default, the store uses the default Redis client.
To use a https://quarkus.io/guides/redis-reference#multiple-redis-clients[named Redis client] instead, set its name:

[source,properties]
----
quarkus.redis.memory.hosts=redis://memory-host:6379
quarkus.langchain4j.memorystore.redis.client-name=memory
----
