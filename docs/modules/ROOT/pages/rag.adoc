== Overview

Retrieval-Augmented Generation (RAG) is a technique used to enhance the performance of Large Language Models (LLMs) by _augmenting_ the prompt with external, (domain-specific) information retrieved before sending the prompt for inference.
This allows models to reason over information they were not originally trained on, making it ideal for enterprise scenarios with private or constantly evolving data.

== Why RAG?

LLMs are trained on large corpus of data but are inherently static and limited by their training data and cutoff date.
RAG bridges this gap by injecting relevant content from **trusted sources** into the prompt, increasing reliability and accuracy without retraining the model.

Benefits of RAG:

* Reduces hallucinations
* Keeps answers up to date
* Improves answer precision using curated data
* Maintains a smaller context window by injecting only relevant information

== Core Principles

At a high level, a RAG system follows this two-phase process:

1.	#Ingestion#: Documents are ingested, segmented (chunked), embedded into vectors, and stored in an embedding store.
2.	#Retrieval#: At query time, the question is embedded, relevant segments are retrieved via similarity search, and then sent to the LLM along with the query.

== Key Concepts

These concepts are foundational to any RAG-based application:

[cols=“1,3”]
|===
|Concept |Description

|Text Splitter |Divides documents into smaller overlapping or non-overlapping segments for processing.
|Embedding |A dense vector representation of a text segment computed by an embedding model.
|Embedding Model |A model trained to convert text into embeddings preserving semantic meaning.
|Embedding Store |The LangChain4j API (`EmbeddingStore`) these extensions implement. It stores embeddings of text segments for similarity search, and usually the original text as well.
|Vector Store |A synonym for an embedding store; a database optimized for similarity search over embeddings (e.g., PGVector, Chroma, Weaviate).
|Query Embedding |The embedding computed from the user’s question.
|Retriever |A component responsible for finding relevant segments given a query embedding.
|Augmentor |Optional logic used to enhance the retrieved content (e.g., filtering, re-ranking, transformation).
|Prompt Injection |Final step of merging query and retrieved content into a prompt for the model.
|===

== Per-method augmentation

When a `RetrievalAugmentor` is configured on `@RegisterAiService` (or is discovered as a CDI bean), it applies to every method of the AI service.
Some methods however need different documents, and some do not need retrieval at all, in which case augmenting them only results in wasted retrieval calls.
The `@AugmentWith` annotation allows configuring retrieval augmentation on individual methods.

=== Overriding the class-level augmentor

A method annotated with `@AugmentWith` uses the `RetrievalAugmentor` provided by the referenced supplier, overriding the class-level configuration:

[source,java]
----
@RegisterAiService(retrievalAugmentor = GeneralAugmentorSupplier.class)
public interface Assistant {

    String chat(String userMessage);

    @AugmentWith(TechnicalDocsAugmentorSupplier.class)
    String answerTechnicalQuestion(String userMessage);
}
----

Here `chat` uses `GeneralAugmentorSupplier`, while `answerTechnicalQuestion` uses `TechnicalDocsAugmentorSupplier`.

The supplier is resolved as a CDI bean when one exists (consider adding a bean-defining annotation to it), otherwise Quarkus creates an instance by calling its no-arg constructor.
Its `get()` method is called on the first invocation of the annotated method for each AI service instance, the same instance lifecycle as the class-level supplier of `RegisterAiService#retrievalAugmentor()`.

=== Disabling augmentation for a method

Use `AugmentWith.None` when a method should not be augmented at all, even when the AI service declares an augmentor:

[source,java]
----
@RegisterAiService(retrievalAugmentor = GeneralAugmentorSupplier.class)
public interface Assistant {

    String chat(String userMessage);

    @AugmentWith(AugmentWith.None.class)
    String translate(String text);
}
----

Here `chat` is augmented with `GeneralAugmentorSupplier`, while no retrieval is performed for `translate`.

Methods without `@AugmentWith` keep the behavior defined by `@RegisterAiService`, so sibling methods are unaffected.
`@AugmentWith` is ignored on `default` methods and on image generation methods.

=== Dynamic alternative

When the choice of documents cannot be made statically, a single custom `RetrievalAugmentor` can delegate to other augmentors based on the invoked method, which is available in the augmentation metadata:

[source,java]
----
@ApplicationScoped
public class MethodAwareAugmentorSupplier implements Supplier<RetrievalAugmentor> {

    @Inject
    TechnicalDocsAugmentor technicalDocs;

    @Inject
    GeneralAugmentor general;

    @Override
    public RetrievalAugmentor get() {
        return new MethodAwareAugmentor(technicalDocs, general);
    }
}

public class MethodAwareAugmentor implements RetrievalAugmentor {

    private final RetrievalAugmentor technicalDocs;
    private final RetrievalAugmentor general;

    public MethodAwareAugmentor(RetrievalAugmentor technicalDocs, RetrievalAugmentor general) {
        this.technicalDocs = technicalDocs;
        this.general = general;
    }

    @Override
    public AugmentationResult augment(AugmentationRequest augmentationRequest) {
        String methodName = augmentationRequest.metadata().invocationContext().methodName();
        RetrievalAugmentor delegate = "answerTechnicalQuestion".equals(methodName) ? technicalDocs : general;
        return delegate.augment(augmentationRequest);
    }
}
----
